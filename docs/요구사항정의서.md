## 1. 시스템 개요

### 1.1 목적
맞춤 여행 견적 작성 프로세스를 단일 웹 플랫폼으로 통합하여, 견적 작성 시간을 60분에서 5분으로 단축한다.

### 1.2 시스템 범위
```
[협력사] ──견적 작성──→ [견적 에디터]  ←──검토/수정── [견적 담당자]
                              │
                         버전 관리
                              │
                         [영업 담당자] ──Excel 출력──→ [대리점/고객]
```

### 1.3 용어 정의

| 용어 | 정의 |
|------|------|
| 비딩(Bid) | 특정 여행 상품에 대한 견적 요청 단위. 비딩 코드로 식별 |
| 견적(Quote) | 비딩에 대한 응답. 일정표 + 견적서 세트 |
| 버전(Version) | 견적의 특정 시점 스냅샷. v1.0, v1.1 형식. 불변(Immutable) |
| 일정표 | 여행 일자별 상세 스케줄 문서 |
| 견적서 | 여행 항목별 원가 및 합계를 담은 산출 내역 문서 |
| 템플릿 | 재사용 가능한 기존 패키지 상품의 일정표 데이터 |

## 3. 기능 요구사항

### 3.1 인증 및 권한 관리

**REQ-AUTH-001** 사용자 로그인  
시스템은 허브 계정 기반 로그인을 지원해야 한다. 로그인 성공 시 역할(partner/agent/sales)이 세션에 포함되어야 한다.  
우선순위: P0 | 출처: PRD §3

**REQ-AUTH-002** 역할 기반 접근 제어  
모든 API 엔드포인트는 서버사이드에서 요청자의 역할을 검증해야 한다. 클라이언트가 전달하는 역할 정보는 신뢰하지 않는다.  
우선순위: P0

**REQ-AUTH-003** 세션 만료 처리  
세션 만료(8시간) 중 편집 중인 데이터는 로컬스토리지에 임시 저장 후 재로그인을 유도해야 한다.  
우선순위: P1

---

### 3.2 비딩 및 견적 관리

**REQ-POPUP-001** 팝업 진입 및 초기화 ⭐신규  
에디터는 기존 견적서 상세 화면에서 팝업 형태로 실행되어야 한다. 팝업 실행 시 URL 파라미터 `quoteNo`와 `role`을 수신하여 해당 견적의 최신 버전 데이터를 자동으로 로드해야 한다.  
예: `/editor/popup?quoteNo=QC00687628001&role=agent`  
우선순위: P0

**REQ-POPUP-002** 팝업 닫기 처리 ⭐신규  
팝업 닫기 시 미저장 변경사항이 있는 경우 "저장하지 않고 닫으시겠습니까?" 확인 팝업을 표시해야 한다.  
우선순위: P0

**REQ-POPUP-003** 부모 창 갱신 ⭐신규  
저장 완료 시 부모 창(견적서 상세 화면)에 `postMessage({ type: 'SAVE_COMPLETE', quoteNo: '...', versionNo: 'v1.1' })`를 전달하고, 부모 창은 이를 수신하여 자동 새로고침해야 한다. 팝업은 자동 종료하지 않고 사용자가 닫기 버튼으로 종료한다.  
우선순위: P1

---

**REQ-BID-001** 비딩 목록 조회  
사용자는 본인 역할에 맞는 비딩 목록을 조회할 수 있어야 한다. 목록에는 비딩 코드, 상품명, 여행 지역, 기간, 상태, 최종 수정일이 표시된다.  
우선순위: P0

**REQ-BID-002** 비딩 상태 관리  
비딩 상태는 OPEN → SELECTED → CONFIRMED → CLOSED 순으로 변경된다. 상태 역행은 불가하다.  
우선순위: P1

**REQ-QUOTE-001** 견적 생성  
협력사와 견적 담당자는 비딩에 대한 견적을 새로 생성할 수 있다. 생성 시 빈 에디터 또는 템플릿에서 시작할 수 있다.  
우선순위: P0

**REQ-QUOTE-002** 견적 조회  
사용자는 권한 범위 내의 견적을 조회할 수 있다. 조회 시 최신 버전이 기본으로 표시된다.  
우선순위: P0

### 3.3 검색 및 불러오기 팝업 (F-01)

**REQ-SEARCH-001** 패키지 템플릿 검색 → **2차 이후**  
~~지역 + 여행 기간 조건으로 기존 패키지 상품 템플릿을 검색~~  
*2차에서 하나투어 상품 DB 실 연동 후 구현*

**REQ-SEARCH-002** 상품코드 직접 입력 (MCP 연동) ⭐변경  
사용자가 하나투어 상품코드를 입력하면 **MCP를 통해 하나투어 상품 DB를 실시간으로 조회**하여 해당 상품의 일정 데이터를 불러올 수 있어야 한다. 결과를 에디터에 자동 세팅한다.  
우선순위: P0 | MCP: 하나투어 상품 데이터 MCP

**REQ-SEARCH-003** 과거 견적 자동 제안 → **2차 이후**  
~~동일 지역 + 동일 기간의 내가 작성했던 견적 데이터를 자동으로 제안~~  
*2차에서 구현*

**REQ-SEARCH-004** 파일 첨부 파싱  
사용자는 엑셀(.xlsx), PDF, HWPX(.hwpx) 파일을 첨부하여 파싱된 데이터를 에디터에 세팅할 수 있어야 한다. PDF는 일반 텍스트 추출을 우선하고, 추출 텍스트가 부족한 이미지형 PDF는 OCR fallback을 수행해야 한다. 구형 Excel(.xls)은 보안상 지원하지 않으며 .xlsx 변환을 안내한다. 구형 한글(.hwp)은 지원하지 않으며 .hwpx 또는 PDF 변환을 안내한다. 파싱 실패 시 텍스트 직접 입력으로 안내한다.  
우선순위: P2

**REQ-SEARCH-004-1** 파일 파싱 품질 보정  
파일 파싱은 AI 파서와 기본 표 파서 후보를 함께 평가해야 한다. 이미지형 PDF는 OCR 텍스트를 원문으로 사용해 동일한 품질 비교를 수행해야 한다. 표 형태 원문에 식사 열(조/중/석, 조식/중식/석식) 또는 숙소/호텔 열이 있으면 해당 원문 값을 우선 보정값으로 사용해야 한다. AI 결과가 품질 기준을 충족하지 못하거나 표 파서가 더 안정적인 경우 기본 표 파서 결과로 불러오고, 사용자에게 진단 메시지를 표시해야 한다.  
우선순위: P1

**REQ-SEARCH-005** 미리보기 제공  
상품코드 조회 결과를 에디터 세팅 전에 미리보기로 확인할 수 있어야 한다.  
우선순위: P1

**REQ-SEARCH-006** 부분 편집 허용  
불러온 일정은 전체 교체 또는 특정 일자만 부분 편집이 가능해야 한다.  
우선순위: P1

### 3.4 일정표 에디터 (F-02)

**REQ-ITIN-001** 헤더 입력  
단체명, 작성일(자동 입력, 수정 가능)을 입력할 수 있어야 한다.  
우선순위: P0

**REQ-ITIN-002** 견적 개요 테이블  
수신, 여행도시, 여행기간, 인원(성인/아동/유아/인솔자), 1인실 추가비용, 여행요금(인당/총액/카드결제시)을 입력할 수 있어야 한다. 각 항목에 비고 컬럼이 있어야 한다.  
우선순위: P0

**REQ-ITIN-003** 일정 기본 항목  
항공/차량, 숙박, 포함사항, 불포함사항, 선택관광, 쇼핑센터, 유의사항을 입력할 수 있어야 한다.  
우선순위: P0

**REQ-ITIN-004** 일자별 블록 UI — 다중 항목 지원 
N박 N일 구조로 일자별 블록이 생성되어야 한다. 각 블록에는 이동/관광/식사/숙박/기타 항목을 **제한 없이 여러 개** 추가할 수 있다. **동일 구분이 같은 일차에 여러 개 존재할 수 있다.**  
예) 1일차: 관광-센토사섬, 관광-국립식물원, 관광-스카이파크 (관광 3개)  
우선순위: P0

**REQ-ITIN-005** 드래그앤드롭  
일정 항목을 드래그앤드롭으로 같은 일자 내 순서 변경 및 다른 일자로 이동할 수 있어야 한다.  
우선순위: P1

**REQ-ITIN-006** 숙박 자동 고정  
숙박 항목은 해당 일차의 마지막 줄에 자동으로 고정되어야 한다.  
우선순위: P1

**REQ-ITIN-007** 식사 세분화 입력  
식사 항목은 조식/중식/석식을 각각 독립적으로 입력할 수 있어야 한다. 각각 내용과 메뉴를 입력할 수 있다.  
우선순위: P0

**REQ-ITIN-008** 푸터 자동 생성  
안내 문구("상기 일정은 항공 및 현지 사정에 의해 다소 변경될 수 있습니다.")와 작성일, "(주) 하나투어"가 자동으로 표시되어야 한다.  
우선순위: P0

### 3.5 견적서 에디터 (F-03)

**REQ-QUOTE-E-001** 견적 항목 자동 연동  
일정표에 입력된 항목(항공, 숙박, 관광, 식사, 차량 등)이 견적서 에디터에 자동으로 행을 생성해야 한다. 자동 생성 수량은 일정표의 성인 인원수를 기본값으로 사용한다. 항목 구분 순서: 항공 → 숙박 → 관광 → 식사 → 차량 → 가이드 → 기타.  
우선순위: P0

**REQ-QUOTE-E-002** 단가 입력 및 자동 계산  
사용자가 항목별 단가와 통화를 입력하면 인원/개수 × 단가 × 환율 = 원화 합계가 자동으로 계산되어야 한다. 항목별 합계, 구분별 합계, 경비 합계가 실시간으로 갱신되어야 한다.  
우선순위: P0

**REQ-QUOTE-E-003** 원가 참고 단가  
내부 원가 DB와 동일 항목이 있는 경우, 참고 단가를 회색 글씨로 표시해야 한다. 강제 반영이 아니며 협력사가 자유롭게 수정할 수 있다.  
우선순위: P1

**REQ-QUOTE-E-004** 총 경비 자동 계산  
예상 총 경비 합계, 지상비수익(협력사 입력), 하나투어수익(수동 입력), VAT(하나투어수익 기준 자동 계산), 총 합계가 자동으로 계산되어야 한다. 에디터에서는 지상비수익과 하나투어수익의 1인당 금액을 표시한다. 미리보기와 Excel 출력에서는 지상비수익을 별도 노출하지 않고 `여행사수수료` 행에 지상비수익 + 하나투어수익 합산 금액을 표시한다.  
우선순위: P0

**REQ-QUOTE-E-005** 미리보기  
제출 전 실제 출력 레이아웃과 동일한 미리보기 화면을 제공해야 한다. 견적서 미리보기와 Excel에는 총 경비 섹션 아래에 `이 견적은 yyyy년 m월 d일 까지만 유효합니다` 문구를 우측 정렬로 표시한다.  
우선순위: P1

**REQ-QUOTE-E-006** 가격 표시 방식 선택  
영업 담당자는 고객 성향에 따라 가격 표시 방식(상세 / 총액 / 숨김)을 선택할 수 있어야 한다.  
우선순위: P1

### 3.6 항공 실시간 조회 팝업 (F-04)

**REQ-FLIGHT-001** 입력 조건  
출발일, 출발편 출발 공항, 출발편 도착 공항, 도착일, 도착편 출발 공항, 도착편 도착 공항을 입력받아야 한다.  
우선순위: P1

**REQ-FLIGHT-002** 조회 결과 출력  
하나투어 그룹/인디비 항공 스케줄 목록을 조회하여 표시해야 한다. 성인 1인당 항공 요금, 유류할증료, 제세공과금, 총 금액을 보여줘야 한다. (1차: Mock 데이터)  
우선순위: P1

**REQ-FLIGHT-003** 접근 권한  
항공 조회 기능은 견적 담당자(agent)와 영업 담당자(sales)만 사용할 수 있다. 협력사에게는 버튼이 노출되지 않아야 한다.  
우선순위: P0

### 3.7 버전 관리 (F-05)

**REQ-VER-001** 최초 버전 생성  
협력사가 견적을 최초 제출하면 v1.0이 생성되어야 한다. 
우선순위: P0

**REQ-VER-002** 자동 버전 채번  
이후 어떤 역할이든 수정 저장 시 v1.1, v1.2, v1.3 형식으로 자동 채번된 새 버전이 생성되어야 한다.  
우선순위: P0

**REQ-VER-003** 기존 버전 불변 보존  
기존 버전은 읽기 전용으로 영구 보존되어야 한다. 덮어쓰기는 절대 불가하다.  
우선순위: P0

**REQ-VER-004** 버전 메타데이터  
각 버전에는 버전 번호, 저장자(이름 + 역할), 저장 일시(UTC), 변경 사유(선택 입력)가 저장되어야 한다.  
우선순위: P0

**REQ-VER-005** 버전 목록 UI  
에디터 화면에서 버전 목록 탭을 통해 전체 버전 이력을 확인할 수 있어야 한다.  
우선순위: P0

**REQ-VER-006** 구버전 읽기 전용 미리보기  
버전 목록에서 특정 버전 클릭 시 해당 시점의 일정표·견적서가 읽기 전용으로 표시되어야 한다. 모든 입력 필드가 비활성화되어야 한다.  
우선순위: P0

**REQ-VER-007** Diff 뷰  
두 버전 간 변경 내용을 시각적으로 비교할 수 있어야 한다. 항목 추가(초록), 삭제(빨강+취소선), 단가 변경(₩X → ₩Y, +N%) 형식으로 표시되어야 한다.  
우선순위: P1

**REQ-VER-008** 변경 사유 입력  
저장 시 변경 사유 입력 모달을 표시해야 한다. 입력은 선택사항이며, 비워도 저장은 진행된다.  
우선순위: P1

### 3.8 Excel 출력 (F-06)

**REQ-EXCEL-001** 여행일정표 출력  
여행일정표를 하나투어 공식 양식에 맞는 .xlsx 파일로 다운로드할 수 있어야 한다.  
우선순위: P0

**REQ-EXCEL-002** 견적산출내역서 출력  
견적산출내역서를 하나투어 공식 양식에 맞는 .xlsx 파일로 다운로드할 수 있어야 한다.  
우선순위: P0

**REQ-EXCEL-003** 파일명 규칙  
다운로드 파일명은 다음 형식을 따른다.  
- 일정표: `여행일정표_{상품명}_{비딩코드}_{견적번호}_{YYYY-MM-DD}.xlsx`  
- 견적서: `견적산출내역서_{상품명}_{비딩코드}_{견적번호}_{YYYY-MM-DD}.xlsx`  
예: `여행일정표_쿨인싱아웃4박_1209_QA0058262301_2026-03-18.xlsx`  
예: `견적산출내역서_쿨인싱아웃4박_1209_QA0058262301_2026-03-18.xlsx`  
우선순위: P0

**REQ-EXCEL-004** 버전 기준 출력  
특정 버전을 기준으로 출력할 수 있어야 한다. 구버전 출력도 가능해야 한다.  
우선순위: P1

**REQ-EXCEL-005** 인감 가이드 영역 ⭐신규  
견적산출내역서 Excel 출력 시 서명/인감을 날인할 위치를 가이드하는 영역이 포함되어야 한다. 가이드 영역은 점선 테두리 원형 또는 사각형으로 표시하며 "(인)" 텍스트를 포함한다. 실제 인감 이미지는 출력에 포함하지 않는다.  
우선순위: P0

## 4. 비기능 요구사항

### 4.1 성능 요구사항

**REQ-PERF-001** 에디터 최초 로딩은 2초 이내(LCP 기준)여야 한다.  
**REQ-PERF-002** 버전 저장 API 응답은 1초 이내여야 한다.  
**REQ-PERF-003** Excel 파일 생성은 100개 항목 기준 5초 이내여야 한다.  
**REQ-PERF-004** 자동 계산(합계)은 입력 변경 시 즉시 갱신되어야 하며, 사용자가 입력 중인 값과 저장되는 계산 결과가 지연 없이 일치해야 한다.

### 4.2 가용성 요구사항

**REQ-AVAIL-001** 서비스 목표 가용성: 99% 이상 (월 기준 7.2시간 이하 다운타임)  
**REQ-AVAIL-002** 정기 점검은 업무 외 시간(평일 23:00~06:00)에 진행한다.

### 4.3 확장성 요구사항

**REQ-SCALE-001** 동시 편집 사용자 50명까지 성능 저하 없이 지원해야 한다.  
**REQ-SCALE-002** 견적 건당 버전 이력은 최대 100개까지 지원해야 한다.

### 4.4 유지보수성

**REQ-MAINT-001** API 응답 시간, 에러율을 모니터링할 수 있어야 한다.  
**REQ-MAINT-002** 배포는 롤백이 가능한 방식으로 수행되어야 한다.

**CON-001** 플랫폼: Next.js 기반 웹 애플리케이션으로 구현한다.  
**CON-002** DB: 현재 로컬 개발은 SQLite + Prisma ORM을 사용하며, 운영 환경은 PostgreSQL 전환을 전제로 한다.  
**CON-003** 외부 API(항공, 원가 DB): 1차에서는 Mock으로 구현한다.  
**CON-004** 삭제 기능은 구현하지 않는다. (데이터 영구 보존 정책)  
**CON-005** 모바일 최적화는 1차 범위에서 제외한다.

## 8. 보안 요구사항

**REQ-SEC-001** 모든 통신은 HTTPS(TLS 1.2 이상)를 사용해야 한다.  
**REQ-SEC-002** 인증 토큰은 서버사이드 세션 또는 JWT로 관리한다. 만료 시간 8시간.  
**REQ-SEC-003** 모든 사용자 입력은 서버사이드에서 XSS 방지 처리를 해야 한다.  
**REQ-SEC-004** API 요청에는 CSRF 토큰 또는 SameSite 쿠키 정책을 적용해야 한다.  
**REQ-SEC-005** DB 쿼리는 파라미터 바인딩(Prepared Statement)을 사용해야 한다.  
**REQ-SEC-006** 민감 정보(비밀번호, 토큰)는 로그에 기록하지 않아야 한다.  
**REQ-SEC-007** 파일 다운로드 URL은 인증된 사용자만 접근 가능해야 한다.
