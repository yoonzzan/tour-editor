## 1. 문제 정의

### 현재 상황
맞춤 여행 견적 작성 프로세스가 다음과 같이 파편화되어 있다.

- **소통 채널 분산**: 하나톡, 메신저, 이메일이 혼용되어 커뮤니케이션 추적 불가
- **도구 파편화**: 엑셀, 워드, PDF, 카카오톡 등 각자 다른 포맷으로 작성
- **재작업 반복**: 협력사 제출 → 담당자 재작업 → 영업 재포맷 → 고객 전달 과정에서 동일 내용을 3회 이상 수작업
- **이력 관리 불가**: 어떤 버전이 최종인지, 무엇이 변경됐는지 추적 불가
- **데이터 소실**: 과거 견적 데이터가 개인 PC와 메신저에 흩어져 재활용 불가

### 핵심 문제
> **견적 1건 작성에 평균 1시간 소요. 이 중 실제 기획 시간은 10분이며, 나머지 50분은 포맷 맞추기, 복사·붙여넣기, 파일 변환에 낭비된다.**

## 2. 목표 및 성공 기준

### 목표
협력사부터 영업 담당자까지 모든 이해관계자가 **단일 웹 에디터**에서 견적서·일정표를 작성하고, 버전별로 관리하며, 고객에게 신속하게 전달한다.

### 성공 기준 (측정 가능)

| 지표 | 현재 | 목표 | 측정 방법 |
|------|------|------|-----------|
| 견적 1건 작성 시간 | 60분 | **5분** | 에디터 최초 열람 ~ 제출 완료 타임스탬프 |
| 담당자 재작업 시간 | 30분 | 0분 | 담당자의 에디터 수정 횟수 |
| 견적 회신 리드타임 | 측정 불가 | 비딩 후 24시간 이내 | 비딩 생성 ~ v1.0 제출 시각 차이 |
| 버전 충돌 건수 | 빈번 | 0건 | 버전 덮어쓰기 에러 발생 건수 |

## 3. 사용자 및 시나리오

### 3.1 사용자 역할

| 역할 | 설명 | 주요 니즈 |
|------|------|-----------|
| **협력사 (Partner)** | 해외 현지 또는 국내 여행사. 비딩 코드 기반으로 견적 제출 | 빠른 비딩 제출, 재작업 최소화 |
| **견적 담당자 (Agent)** | 비딩 결과 취합·비교, 최적 견적 선정 | 비딩 비교, 원가 검토, 항공 요금 확인 |
| **영업 담당자 (Sales)** | 고객용 최종 문서 편집 및 발송 | 최종 일정/마진 조정, 히스토리 확인, 대리점 발송용 문서 |

### 3.2 에디터 진입 방식

에디터는 **독립 앱으로 직접 접근하지 않는다.** 하나투어 기존 견적서 상세 화면에서 팝업으로 실행된다.

```
[하나투어 기존 시스템 — 견적서 상세 화면]
  견적번호: QC00687628001 | 청발 장가계 5일
       │
       │ 담당자가 "에디터 열기" 버튼 클릭
       ▼
  ┌──────────────────────────────────────────┐
  │  견적 에디터 팝업  (최소 1280×900px)      │
  │  ┌────────────────────────────────────┐  │
  │  │  일정표 탭  │  견적서 탭           │  │
  │  │  ...편집...                        │  │
  │  └────────────────────────────────────┘  │
  │  [저장 → v1.1 생성]  [닫기]             │
  └──────────────────────────────────────────┘
       │ 저장 완료 시 postMessage
       ▼
  부모 창(견적서 상세) 자동 새로고침
```

**진입 URL**: `/editor/popup?quoteNo=QC00687628001&role=agent`

| 파라미터 | 설명 | 비고 |
|---------|------|------|
| `quoteNo` | 견적번호 (기존 시스템 PK) | 필수 |
| `role` | 현재 사용자 역할 | partner / agent / sales |

**팝업 동작 규칙**:
- 팝업 닫기 시 미저장 변경사항 있으면 "저장하지 않고 닫으시겠습니까?" 확인
- 저장 완료 후 부모 창에 `postMessage({ type: 'SAVE_COMPLETE', quoteNo, versionNo })` 전달
- 저장 완료 후 팝업은 자동 종료하지 않고, 사용자가 닫기 버튼으로 종료한다.

### 3.3 사용자 시나리오

#### 시나리오 A: 협력사의 최초 견적 제출
```
1. 협력사가 허브에 로그인 → 견적서 상세 화면 진입
2. "에디터 열기" 클릭 → 팝업 실행 (quoteNo 자동 전달)
3. [검색 팝업] 상품코드 입력 → MCP로 하나투어 상품 일정 불러오기
   └ 상품 없으면 파일 첨부 또는 텍스트 직접 입력
4. 일정표 에디터에서 일자별 일정 입력
   └ 동일 일차에 관광 항목 여러 개 추가 가능
     예) 1일차: 관광-센토사섬, 관광-국립식물원, 관광-스카이파크
5. 견적서에서 항목별 단가 입력 → 합계 자동 계산
6. 미리보기로 출력 레이아웃 확인 (인감 위치 가이드 확인 포함)
7. 저장 → v1.0 생성 → 부모 창에 저장 완료 이벤트 전달 → 필요 시 사용자가 팝업 닫기
```

#### 시나리오 B: 담당자의 견적 검토 및 수정
```
1. 담당자가 견적서 상세 화면에서 "에디터 열기" 클릭
2. v1.0 내용 검토 — 원가, 단가, 일정 확인
3. 수정 필요 항목 편집 (단가 변경, 일정 항목 추가/삭제 등)
4. 저장 → 변경 사유 입력 → v1.1 생성
5. 버전 패널에서 v1.0 vs v1.1 Diff 확인
```

#### 시나리오 C: 영업 담당자의 고객용 문서 발송
```
1. 영업 담당자가 견적서 상세 화면에서 "에디터 열기" 클릭
2. 최종 일정/마진과 가격 표시 방식 조정 (총액/상세/숨김) → 저장 → v1.2
3. Excel 다운로드 → 여행일정표 + 견적산출내역서 (.xlsx)
   └ 견적산출내역서 하단에 인감 위치 가이드 영역 포함
4. 인감 날인 후 대리점 전달
```

#### 시나리오 D: 구버전 조회
```
1. 에디터 팝업의 버전 패널에서 과거 버전 클릭
2. 해당 시점 일정표·견적서 읽기 전용 표시
3. 현재 버전과 Diff 뷰 비교
```

## 4. 1차 범위 (In Scope)

### 포함
- **에디터 팝업 진입** — 기존 견적서 상세 화면(quoteNo)에서 팝업 실행
- 견적 에디터 (일정표 + 견적서 통합 편집)
- 검색 팝업 — **상품코드 입력 (MCP 연동)** + 파일 첨부 + 직접 입력
- 버전 관리 및 이력 추적 (Diff 뷰 포함)
- Excel 출력 — 여행일정표, 견적산출내역서 (**인감 가이드 영역 포함**)
- 항공 실시간 조회 (Mock 구현)
- 역할 기반 권한 분리

### 제외 (2차 이후)
- 패키지 템플릿 검색 (지역+기간 조건 검색)
- 과거 견적 자동 제안
- 웹 전용 제안서 링크 생성 및 발송
- 하나톡 연동
- 자동 견적 시스템 (AI 자동 작성)
- 알림 기능 (이메일, 푸시, 하나톡)
- 모바일 최적화
- 다국어 지원

## 6. 에러 및 예외 처리 정책

### 6.1 네트워크/저장 오류
| 상황 | 처리 방법 |
|------|-----------|
| 저장 중 네트워크 끊김 | 30초마다 로컬스토리지 자동 임시 저장. 재연결 시 서버 저장 재시도 3회 |
| 저장 재시도 3회 실패 | "저장 실패" 토스트 + 로컬스토리지 임시 저장 유지. 수동 재시도 버튼 제공 |
| 버전 생성 실패 | 이전 버전 상태 유지. 사용자에게 에러 메시지 표시. 데이터 유실 없음 |

### 6.2 동시 편집 충돌
| 상황 | 처리 방법 |
|------|-----------|
| 동일 견적을 두 명이 동시에 열었을 때 | 낙관적 잠금(Optimistic Lock). 저장 시 버전 번호가 다르면 충돌 알림 |
| 충돌 발생 시 | "다른 사람이 이미 수정했습니다. 최신 버전을 불러오시겠습니까?" 팝업 |
| 충돌 해결 | 사용자가 최신 버전을 불러오거나, 자신의 변경사항을 새 버전으로 강제 저장 |

### 6.3 파일 업로드/파싱 오류
| 상황 | 처리 방법 |
|------|-----------|
| 엑셀 파일 파싱 실패 | "파일 형식을 읽을 수 없습니다. 다른 방법을 선택해주세요." 안내 |
| PDF 텍스트 추출 부족 | 페이지 이미지 OCR fallback 수행 후 기존 파서로 재시도 |
| PDF OCR/파싱 실패 | 동일 안내. 텍스트 직접 입력으로 대체 유도 |
| 파일 용량 초과 (10MB 이상) | 업로드 전 클라이언트 사이드 검증으로 차단 |

### 6.4 외부 API 오류 (항공 조회)
| 상황 | 처리 방법 |
|------|-----------|
| 항공 API 응답 없음 (1차: Mock) | Mock 데이터 반환. 실 API 연동 전까지 항상 Mock |
| Mock 응답 지연 (의도적 500ms) | 로딩 스피너 표시. UX 리얼리즘 확보 |

### 6.5 권한 오류
| 상황 | 처리 방법 |
|------|-----------|
| 권한 없는 페이지 직접 URL 접근 | 403 페이지로 리다이렉트 |
| 세션 만료 중 편집 | 저장 시도 시 "세션이 만료됐습니다" 팝업. 로컬스토리지 임시 저장 후 재로그인 유도 |
| 협력사가 타 비딩 코드 직접 입력 접근 | API 레벨에서 차단. 404 응답 |

## 7. 외부 시스템 연동

### 1차 연동 방식

| 시스템 | 연동 방식 | 비고 |
|--------|---------|------|
| **하나투어 상품 DB** | **MCP 연동** (실 연동) | 상품코드 입력 시 실시간 조회 |
| 항공 스케줄 API | Mock JSON | 2차에서 실 API 연동 |
| 원가 참조 DB | Mock 단가 데이터 | 2차에서 실 연동 |
| 기존 견적서 시스템 | quoteNo 파라미터 수신 | 팝업 진입 시 |

### Mock 데이터 경로
```
src/mocks/
├── flights.json         # 항공 스케줄 샘플
├── cost-reference.json  # 원가 참고 단가 샘플
└── templates.json       # 패키지 템플릿 샘플
```

## 8. 비기능 요구사항

### 8.1 성능
| 항목 | 기준 |
|------|------|
| 에디터 최초 로딩 | 2초 이내 (LCP 기준) |
| 버전 저장 응답 | 1초 이내 |
| Excel 파일 생성 | 5초 이내 (100개 항목 기준) |
| 버전 목록 로딩 | 1초 이내 |

### 8.2 브라우저 지원
- Chrome 최신 2개 버전
- Safari 최신 2개 버전
- Edge 최신 2개 버전
- Firefox는 미지원 (내부 도구 특성상 제외)

### 8.3 화면 해상도
- 최소: 1280×800 (데스크톱 최적화)
- 모바일/태블릿: 1차 미지원 (레이아웃 깨질 수 있으나 기능은 동작)

### 8.4 보안
- HTTPS 필수
- 세션 토큰: JWT, 만료 8시간 (업무 시간 기준)
- API: 모든 엔드포인트 서버사이드 역할 검증
- 입력값: XSS 방지 (서버사이드 이스케이프)
- 파일 다운로드: 인증된 사용자만 접근

### 8.5 데이터 보존
- 견적 버전: 영구 보존 (삭제 기능 없음)
- 로컬스토리지 임시 저장: 브라우저 세션 종료 후 7일 유지
- 로그: API 요청/응답 로그 30일 보존

### 8.6 접근성
- WCAG 2.1 AA 준수 (핵심 편집 기능 한정)
- 키보드 단축키: Tab 순서 논리적 구성
- 에러 메시지: 스크린 리더 호환 (`role="alert"`)
